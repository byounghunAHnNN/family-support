## 2. 패키지 구조 (DDD)

정산앱과 같다 — 영역별 `domain / application(command·query) / infrastructure / interfaces`.

```
com.familysupport.app
├─ common/    ApiResponse·예외·GlobalExceptionHandler·Clock·캐시 금지 필터
├─ benefit/   지원사업(Aggregate 루트 Benefit) · 내 상황 판정 · 검색 API
│   ├─ domain/          Benefit, BenefitDraft, Benefits(컬렉션), HouseholdProfile, SupportConditions,
│   │                   Eligibility, Region, LifeStage, BenefitClassifier, MedianIncome, IncomeBand
│   ├─ application/query/ BenefitQueryService
│   ├─ infrastructure/  BenefitJpaRepository
│   └─ interfaces/      BenefitController, BenefitMapper, Request/Response
└─ collect/   수집(Aggregate 루트 CollectRun) · 출처별 API 호출 · 스케줄
    ├─ domain/          BenefitFeed(출처 인터페이스), CollectRun, FeedException
    ├─ application/     command/CollectCommandService, query/CollectQueryService
    ├─ infrastructure/  Gov24Feed, BokjiroCentralFeed, BokjiroLocalFeed, PublicDataHttp, XmlItems
    └─ interfaces/      CollectScheduler, CollectController(local만), CollectStatusController
```

- **collect는 benefit의 Repository로 Benefit을 저장한다.** 수집의 결과물이 곧 지원사업이라 이 방향의 의존만 허용한다(benefit은 collect를 모른다).
- 출처 API 호출은 `collect/domain/BenefitFeed` 인터페이스 뒤에 숨긴다. 출처를 추가하면 구현체(`@Component`)만 늘리면 된다.

## 3. 정산앱 규칙과 같은 것

- 컨트롤러는 `return ApiResponse.ok(mapper.toResponse(service.x(mapper.toXxx(request))))` 한 문장, 단계마다 줄바꿈. 지역 변수·분기·try-catch 없음.
- 응답은 `ApiResponse{success,data,error}`, 예외 변환은 `GlobalExceptionHandler` 한곳.
- DTO·VO는 `record`, 엔티티는 setter 없이 정적 팩토리(`create`)·의미 있는 메서드(`refresh`)로만 바꾼다.
- Mapper는 영역당 하나 직접 작성(MapStruct 안 씀).
- **Repository는 JpaRepository 기본 메서드만**(findAll·findById·save·saveAll·deleteAll·count). 거르기·정렬은 도메인 컬렉션(`Benefits`)에서.
  - 알고 택한 비용: 검색마다 사업 전체(수천 건)를 읽는다. 사용자가 늘면 `Benefits`를 만드는 지점만 바꿔 끼운다(캐시 등).
- 주석은 한국어로 "무엇·왜". 엔티티는 Aggregate 루트 여부를 적는다.

## 4. 이 앱에서 다른 점

| 항목 | 내용 | 이유 |
|---|---|---|
| 로그인 없음 | 인증·사용자 영역 없음 | 개인 정보를 서버에 두지 않는다 |
| 검색은 POST | `POST /api/benefits/search` | 소득·가구 상황을 URL·로그에 남기지 않기 위해(정산앱 5장 "민감값은 POST 본문") |
| 입력 저장 | 브라우저 `localStorage`에만 | 서버 저장 없음 |
| 수집 서비스 트랜잭션 | `CollectCommandService`는 클래스 `@Transactional` 없음 — 저장만 `TransactionTemplate` | 외부 호출이 수 분 걸려 그동안 트랜잭션을 잡지 않으려고 |
| 수동 수집 API | `family.collect.manual-enabled=true`(local)일 때만 존재 | 인증이 없어 운영에서 열어 두면 누구나 수집을 돌릴 수 있다 |

## 5. 판정 원칙 (benefit 도메인)

**"확실히 안 되는 것만 제외하고, 애매한 것은 '확인 필요'로 남긴다."** 데이터의 조건 정보가 거칠기 때문이다.

| 조건 | 처리 |
|---|---|
| 지역 | 다른 시도·시군구 → 제외. 시군구 미선택이면 같은 시도의 시군구 사업 → 확인 필요 |
| 가구 상황 | 고른 상황과 겹치지 않으면 제외. 안 고르면 거르지 않음 |
| 나이(정부24) | 상한 18세 이하 = 아이 나이로 보고 범위 밖이면 제외. 그 밖은 신청자 나이로 보고 범위 밖이면 **확인 필요**(누구 나이인지 데이터에 없음). 상한 100 이상 = 제한 없음 |
| 소득(정부24) | 연 소득 ÷ 12 ÷ 2026 기준 중위소득. 허용 안 하는 구간 → 제외. 허용되는 가장 높은 구간(실제 기준선이 구간 안) → 확인 필요. 7인 이상 → 확인 필요 |
| 가구유형(정부24) | JA0410(해당없음)이 없고 무주택·다자녀 등이 지정됐는데 내 입력과 안 맞으면 → 확인 필요 |
| 복지로 | 조건 코드가 없어 항상 확인 필요 + 관련 가구유형 표시 |

- 기준 중위소득 표(`MedianIncome`)는 매년 바꾼다(매년 8월 고시, 다음 해 1월 적용).

## 6. 수집

| 출처 | 방식 | 주의 |
|---|---|---|
| 정부24 | 전체 목록 1,000건씩 → 대상 후보만 지원조건 1건씩 호출 | 소관기관명 필터가 API에 없음. 원문 수정일이 같으면 저장된 조건 재사용 |
| 복지로 중앙 | 500건씩 | 전부 전국 사업 |
| 복지로 지자체 | 대상 시도별 100건씩, 대기 120초·3회 시도 | 응답이 느림(인천 첫 쪽 25.6초 실측). 시도 하나라도 실패하면 출처 전체 실패 처리 |

- 매일 05:00(한국 시간) + 서버 시작 시 저장본이 비었으면 1회.
- 실패한 출처의 기존 저장본은 지우지 않는다. 성공한 출처에서 안 나온 사업은 지운다.
- 같은 사업이 출처 여러 곳에 있으면 **합치지 않고** 각각 저장·표시(이름만으로 병합하면 틀린다).
- **재시도는 HTTP 오류뿐 아니라 본문 오류도 대상**(`PublicDataHttp.get(..., parser)`): 복지로 지자체가 HTTP 200 + `resultCode=99`를 간헐적으로 준다(11/16 실측 — 같은 요청 0.5초 성공 2회, 30초 뒤 99 1회). 시도 사이 3초 대기.
- **원문 문구는 컬럼 길이에 맞춰 자른다**(`Benefit.refresh` → `fit`): 11/16 첫 수집에서 문의처 553자가 컬럼 500자를 넘어 저장 전체가 롤백됐다. 컬럼도 넉넉히 늘렸다. 링크(URL)는 자르면 깨지므로 길이 초과 시 버린다.
- 저장 단계 예외로 롤백되면 실행 기록을 별도 트랜잭션으로 `FAILED` 처리한다(RUNNING으로 남지 않게).
- 오류 메시지·수집 기록에 URL을 넣지 않는다 — URL에 인증키가 들어 있다.

## 7. 테스트

- "통과"를 보고할 때는 실행한 명령과 테스트 개수·실패 수를 함께 적는다.
